# 18 · 领域包：选择、构建与解释

## 1. 先匹配什么

领域包提供一组已发表论文的描述性参照，不是质量标准，也不等于整个学科的代表性样本。先同时核对语言、体裁、章节功能、研究设计、期刊和主题；不能只因学科标签相同就混合统计。实证论文、方法教程、理论构想、系统综述、元分析和质性研究的章节职责不同。

写作仍以问题、证据和读者需要为依据。没有合适的领域包，可用 3–5 篇相近全文逐篇对照；不能为了有分位数而借用不匹配的包，也不必因此停写初稿。

## 2. 随包参照与证据边界

| 包 | 入选篇数 | 范围 |
|---|---:|---|
| psychology_zh | 22 | 《心理学报》中文定量实证：实验 11、调查 9、量表编制 2 |
| education_zh | 11 | 《开放教育研究》中文原始数据实证：调查 5、实验 4、二次数据分析 1、预测模型 1 |
| clinical_psych_en | 24 | 英文临床心理与精神医学实证；具体文献见包内清单 |
| social_perception_en | 18 | 英文社会知觉与生物运动任务：行为任务 13、神经影像 4、计算模型 1 |
| education_psych_en | 11 | 英文学业表现相关观察性研究：调查 10、二次数据分析 1 |

中文包入选条件是全文可用、论文身份可核、无重复、体裁在范围内，分节能支持当前指标。心理学的质性口述史和无法可靠分开方法/结果的混合结构论文不在此范围。教育学的理论框架、综述、元分析和方法案例另留作相应体裁的单篇对标，不进入这个原始数据实证包。文件数量不等于独立论文数量。

两个中文包各来自一种期刊，教育包还有主题集中和易解析结构的选择偏倚。语言、期刊、体裁和主题相互混杂；观察到分布差异不能归因于“中文风格”或“学科文化”。体裁差异检验未显著也不能证明不同体裁等价、可以合并。教育包各体裁都不足 8 篇，不宜以单一体裁子集作稳定分位数参照。

英文社会知觉包包含 PLOS ONE、Scientific Reports、Nature Communications 等期刊，但围绕视觉动作与社会互动任务，不代表全部认知神经科学。神经影像与计算模型子集分别只有 4 和 1 篇；不应与行为任务无条件合并。英文教育心理包均来自 Frontiers in Psychology，关注学业表现相关的观察性研究，不是教育干预或教学实验基线。两个新英文包均不足 20 篇；结论、局限等章节的实际可测篇数更少，须保留工具提示。原临床心理英文包保留已有 24 篇统计；它与新包是不同范围，不能拼成一个通用英文标准。

英文包采用公开全文 XML，经 DOI 核对、正文分节和元数据校正后构建；主题式合并章节无法可靠拆分的文章不纳入。构建时规范化明确的同义节标题、保留方法内伦理文字并去掉网页导航。换用原始 PDF 转写或其他版本时，仍须先检查切节。内容指纹只覆盖所建包的文本版本及其去元数据副本；相同 DOI 的不同转写也应人工排除，不能把未触发指纹拦截当作独立文献。

期刊声誉或影响因子不能替代主题、体裁、设计和章节功能的匹配。Nature 主刊、Nature Communications 和 Scientific Reports 是不同期刊；不能混称“Nature论文”，也不能把某刊风格当作跨学科要求。已发表论文中的因果措辞和统计做法仍须独立判断。

来源、体裁、年份和许可记录见各包 corpus_manifest.csv；每节实际篇数、稳定性、句式留一结果与规则触发率见 profile.json、build_report.md。没有独立假阳性真值时，只报告“触发”或“偏离”，不称误报率。

方法学中文材料包含方法教程、综述、文献计量与研究构想，不能因合计达到 8 篇就建成同质实证包。计算机、管理、医学、社会学未随包提供可用分布基线；少量全文或候选索引可用于匹配阅读，不能声称该领域已校准。

## 3. 样本量与统计的读法

- 少量论文可用于语步和信息分配的逐篇对照；领域包 check 至少要求 8 篇。这是工具的使用阈值，不是通用的统计充分性定理。
- bench_profile 和 section_lint 的上界按**每项实际可测 n**决定：不足 10 篇用全范围，10–19 篇用 p10–p90，20 篇及以上用 p05–p95。包共 22 篇不代表每节都有 22 篇。
- phrase_contrast 的偏多判定用参照最大值；language_plan 的模式校准在可测 n≥10 时用 p90，否则用最大值。不同工具的阈值不能混写成同一套。
- stability 逐篇留出，再从其余论文抽 k 篇，与使用其余全部论文的判定比较；分母是可测指标的比较次数。指标相关、同文重复抽样，不能把这些次数当独立样本数或外部验证。
- rule_rates 是本包分布校准后的样本内描述。留一或外部验证要排除被测论文并重建包，不能拿包含它的发布包证明效果。
- 分位数不是应当达到的目标；频繁触发也不证明规则错误。最终回到具体句子的职责、证据和作者意图裁决。

## 4. 使用

```text
python scripts/mslib.py sections manuscript.md
python scripts/bench_profile.py --baseline assets/domains/psychology_zh --draft 稿件=manuscript.md --report bench.md
python scripts/phrase_contrast.py --baseline assets/domains/psychology_zh --draft 稿件=manuscript.md --report phrases.md
python scripts/language_plan.py scan --doc 稿件=manuscript.md --baseline assets/domains/psychology_zh --plan plan.csv
python scripts/section_lint.py manuscript.md --domain assets/domains/psychology_zh --json lint.json
```

mslib sections 只检查切节，不接受 --baseline。三个对标/修订工具支持 --genre；选择前查看子集篇数和各节覆盖。section_lint --domain 使用整个包；需要同体裁校准时另建足够样本且范围一致的包。

四个消费者都会拒绝拿包中原文作自身参照。新建包还保存不含 YAML 目录信息的内容指纹，改文件名或只改元数据不能绕过检查；旧包只能核其已有原文指纹。

常见风格规则可降为 INFO 并注明触发篇数；交付残留、字数要求、因果/设计矛盾、趋势话术、未经验证的建议、新颖性与作者声明规则不因发表频率降级。自动提示仍是待裁决候选，不直接判定科学结论。

## 5. 构建与验收

1. 本地保留全文，逐篇核对题名、DOI、正式年份、体裁、完整性和来源。优先用与稿件接近的论文；文件名、封装 YAML、下载目录和文章正文有冲突时记录取舍。摘要、候选目录、重复文本不算独立全文。
2. 清单列为 file,id,title,journal,year,genre,license，可加 completeness（fulltext、abstract_only 等）。file 支持文件名和相对路径，歧义会报错。**清单提供元数据，不是入选白名单**；将选中文件单独放私有目录，或在 --corpus 中显式传入选中文件，不能把整个混合目录直接交给构建器。
3. 逐篇运行 mslib.py sections，复核摘要、参考文献、无编号图中文字、中文编号标题和合并章节。不能把未识别正文全算作方法或引言。合并方法/结果中只有明确的编号结果小节才另切结果；其余混排需人工定位或暂不用于分节基线。
4. 在独立输出目录构建并检查：

```text
python scripts/domain_pack.py build --corpus 私有入选目录 --manifest 清单.csv --id 领域_语言 --label "范围说明" --field 领域 --lang zh --out 新领域包
python scripts/domain_pack.py check 新领域包
```

5. 检查每节覆盖、缺失、体裁分布和异常指标；警告不足不能改阈值压掉。规则触发日志和领域常态不能代替人工全文核查。

输出七个文件：profile.json、bench_baseline.json、phrase_baseline.json、texture_baseline.json、rule_rates.json、corpus_manifest.csv、build_report.md。同 DOI 或不含 YAML 的同文本会去重；非全文状态、候选索引、无可测正文会排除；不足 3 篇不能构建，少于 8 篇不能通过发布检查。

包内只保留统计、短句式骨架、必要标题与文献元数据，不放全文、段落或原句。长文本字段检查和目录白名单可发现常见混入，不能自动证明所有版权或隐私条件已满足。遵守所用来源的具体许可与本次授权；用户稿件和私人信息另行检查。构建器遇到额外文件/子目录会拒绝，不会替用户删除原件。

词表、模式目录或解析方式变化后，重新评估受影响的包；相应指纹检查不能替代解析结果复核。纹理指纹只覆盖模式目录和它引用的词表键（`domain_pack.texture_fingerprint`）：改了这些要用 build 重建，不能只改指纹。改别的键（如 section_lint N1 用的 overclaim_re）不影响纹理基线，但 rule_rates.json 里对应规则的触发率会过时，有语料时一并重建。维护时还应检查包内引用是否仍指向现有文件，并运行机械测试及隔离行为试用。
