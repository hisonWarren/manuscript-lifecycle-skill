# 图表、说明与实际交付

表题、表注、图注是读者理解证据的入口。它们既不能变成小型方法节，也不能因追求短而删掉样本量、尺度、误差和必要条件。来源与适用边界见 references/15_verified_sources.md（S01–S05）。

## 1. 先建立目标刊规则与图表台账

从当前作者须知记录期刊、文章类型、初投/返修/接收阶段、URL、访问日和具体要求：图表数量、放置位置、标题/注释方式、图像规格、是否双盲、补充文件及引用规则。没有规定的项目不虚构“期刊要求”。

每个 display 记录稳定 ID、正文/补充归属、对应研究问题、结果台账行、文件与散列、首次引用、读者需判断什么。表和图重复展示同一数字须说明各自用途；不能仅因图好看把核心证据放补充、把敏感性分析当主图。

## 2. 表注和图注：最少且充分

先问读者仅看这一图表能否读对。按实际适用项检查：

| 信息 | 应放哪里 | 删除测试 |
|---|---|---|
| 对象、结局、分组或时间点 | 简短标题、行列或面板标签 | 删除后不知道在比较什么则保留 |
| 单位、变量/非标准缩写、符号含义 | 行列标题或注释 | 表内已经明确且不存在歧义的重复可删 |
| N、分母、缺失、参考组、变换尺度 | 表体或必要注释 | 删除后会把效应/百分比/样本读错则保留 |
| 点/线/颜色/面板、误差条与区间 | 图例或图注 | 不应让读者猜点代表人、均值还是模型估计 |
| 检验、单双侧、校正、模型调整 | 依期刊要求与理解必要性在注释说明，完整方法留方法节 | 只删与理解无关的重复，不能隐去影响解释的调整 |
| 数据来源、改绘授权、图像拼接等 | 必要来源/权限说明 | 美化或精炼不能删除 |
| 机制解释、意义、预辩、内部操作日志 | 一般移到讨论或内部记录 | 若不影响读图、期刊也不要求，移出而非堆在注释 |

表题回答“这是什么”；图注解释“各部分怎样读”；不在两处重复完整结果。图注可以依学科含简短结果性标题，不能用通用正则把所有有谓语的标题判错。APA 要求的简洁边框与某些期刊的网格要求不同，优先目标刊。

**对标设计：** 选择相同图表任务和复杂度的全文实例，如多变量回归表与同类回归表比，不能与一行描述表混比。记录题目、注释词数、面板数、需定义缩写/符号数、样本/误差/校正说明、与方法或正文重复的句子。先按功能编码，再算中位数/范围；样本少则逐例比较，不制造百分位精度。长说明是复核信号，必要信息覆盖率才是硬条件。切勿把用户旧脚本里“24 篇/89 表”等数字当本次已核实基准，除非原语料与抽取结果可重建。

**自动抽取：** `python scripts/display_extract.py --draft 稿件.md --exemplar 对标1.md … --out display/display_corpus.json --signals display/signals.md` 抽出表题、表注、图注（合并 PDF 转写中单独成行的“Table 1.”与下一行标题，排除“Table 1 shows…”这类正文提及），自动登记路径、指纹与摘录，生成 display_profile 可直接读取的清单。task 与 panels 是启发式猜测，人工确认后再运行 display_profile。signals.md 标出每条稿件注释的解释句、方法复述、定义、不确定性和样本信息，并对照对标同类型条目的长度与信号比例。实测 24 篇 PDF 转写对标中只有 8 篇能稳定抽出，覆盖不足时逐例比较，不报告百分位。

## 3. 文件检查与视觉验收分开

对已抽取并核过来源的注释，可运行 display_profile.py，按任务、语言、类型和面板数分层；同一论文相同摘录去重，每篇先汇总，输出长度范围与超出范围的复核提示。它不检测正文语义重复。格式见 17。没有可比语料就标无匹配，不与简单表注混合来压短多面板图注。

单独交付的 Highlights、图注表注这类片段，用 `python scripts/section_lint.py 片段.md --fragment [--limits limits.json]` 查字符上限、占位符与交付残留；它不做各节职能检查，不能替代整稿检查。

运行 `scripts/delivery_check.py delivery.json --report delivery_report.json` 检查包内文件、DOCX 残留、结构化图表覆盖与明确的图片元数据要求。清单每项须绑定实际文件和 SHA256；标题/图注/注释摘录必须能在文件中找到。它检查的是显式登记内容，不证明没有漏登记。

另做实际渲染验看并记录页码/图号与版本：表格是否超页、列宽与小数对齐、字体可读、负号/上下标是否正确、表头跨页重复、题注不与图分离、注释没有切断、标签无遮挡、黑白或色觉条件下仍可区分。DOCX XML、文件能打开、DPI 达标都不能冒充视觉验收。导出 PDF 后重新检查；改动后旧截图失效。没有渲染工具就明确记未验看，不能宣称投稿包已完成版式验收。

## 4. 投稿和返修的交付矩阵

从目标刊要求生成 required_roles，不把所有项目强塞给所有用户。常见角色包括干净稿、匿名稿、题名页、投稿信、图源文件、补充材料、报告清单、数据/代码可用性声明、伦理/资金/利益冲突/作者贡献、AI 使用披露；返修增加逐点回复和标记稿。需要作者确认的事实保留显眼占位，不填写假批准号、作者贡献或“无利益冲突”。

每个文件标明用途、版本、是否供上传；逐点回复的修改位置来自最终干净稿；标记稿须确实显示改动；匿名稿检查正文、题名页、页眉页脚、批注与文档属性。还要人工检查自引、单位暗示、伦理机构、致谢、图中作者信息和文件名，自动工具不能保证匿名完整。

补充材料要独立可读、内部编号一致、正文引用能到达；不能假定出版社会替它排版。投稿信不夸大创新，不藏重复发表/相关稿信息；披露按真实使用记录写，目标刊要求重查（S10）。返修最少核对逐点回复、干净稿、标记稿是否为同一版（S11、S13）。

最后交付一份短 README：先打开哪个文件、哪些可上传、哪些仍待作者填实、验证完成到什么程度。审计日志留在工作目录或单独审计包，不与期刊上传材料混装。交付包完整不等于已投稿，实际提交另依用户授权执行。

## 5. delivery_check 接口与限制

清单 schema_version=1；`files` 必须给 `id, path, role, sha256`，路径相对清单且必须留在包目录内；`required_roles` 指本次必须交付的文件用途；`displays` 的 `file_id` 指向文件，每项可声明 `title, caption, note, used_symbols, symbol_definitions, abbreviations, required_explanations, citations`。摘录为实际文字，不是“已检查”打勾。`citations` 每项为 `file_id/text`，正文引用全文另可登记在 `crossrefs`（每项 `target_id/file_id/text`）以检查不存在的目标。`journal` 可配置 `repeat_header`、`vertical_borders` 的 `warn/error/ignore`；`anonymity` 的 `file_ids`、`terms` 是需扫描范围与作者/单位已知特征；图片 `requirements` 支持 `min_pixels: [宽,高]`、`min_dpi`、`width_mm/height_mm`，只在明确要求时检查。PNG pHYs 与 JPEG JFIF 元数据可读；仅 EXIF 的 DPI 无法核实时记为不通过该要求，不能猜测。

退出码 0=这组机械检查无阻断（仍可能有警告），1=发现阻断，2=输入结构错误。报告固定标明 `render_verified=false`，并列出未覆盖项目。任何人可手填清单，故发布门控还须审阅清单覆盖和实际渲染；不能把脚本 PASS 单独作为科学/语言/版式全部通过的证据。

### Word 修订与匿名的检查范围

读取 Word 分两种视图：接受全部修订（终稿文字）与拒绝全部修订（修改前的文字）。两种视图都处理插入、删除、移动、段落标记的删除与插入（合并段、拆分段）和表格整行的增删；拒绝视图的标题级别取属性修订前的样式。正文顶层内容控件（题名、文献表等）照常读取；文本框只读一次并单独成段；Symbol 字体的符号转成对应字符，其他符号字体的私用区编码记为 U+FFFD，需对照原文。域代码不算文字，域结果算。正文视图不含脚注与页眉页脚。

干净稿出现任何修订（含移动和属性修订）即阻断，修订稿允许保留。占位符与域错误按接受修订后的文字判断：修订稿里已删除的占位符不算未解决，新插入的仍阻断。英文文件里出现中文会提示：批注者常把意见直接写成修订插进正文，“全部接受”后就留在稿件里。处理批注稿时先用 `mslib.py annotations` 把批注和逐条修订列出来，标 ⚑ 的插入先单独判断。

匿名检查读正文、脚注、页眉页脚、批注和文档属性，还读删除的文字、修订与批注作者、people.xml、域代码、外部链接目标（如模板路径里的用户名）和文档变量；文件里存着的人名（“Author 1”之类通用标签除外）以提示列出。自引、致谢和图中信息仍须人工检查。

结构识别不等于版式验收：字体、跨页表格与修订显示须实际渲染逐页看，并记录渲染引擎与未测功能。看跨页表时查表头是否重复、行是否被拆到两页（被拆开时，下一页表头下会出现一条看似空白的行，可设“行不跨页”）。仅确认文档能打开或 XML 没有报错，不能称为版式验收。

## 6. 表格版式：三线表与注释顺序

三线表只有三条线：顶线、表头下横线、底线。没有竖线；只有分组栏头下面再加一条横线。表头跨页重复，数据行不跨页，同一列用同一精度。APA 的简洁边框与某些期刊的网格要求不同，**目标刊的体例优先**。

```text
python scripts/table_style.py build --csv 表.csv --title "表题" --label "Table 1" \
       --note "注释" --house nature --decimals 2 --out 表.docx
python scripts/table_style.py check 表.docx --house nature --report table_check.md
```

build 拒绝列数不一致的 CSV（含逗号的字段如 `n = 1,032` 必须加英文双引号），并统一各数值列的小数位。check 查竖线、内部横线、表头重复、行跨页、同列小数位、p 值与区间写法，以及表注顺序。

**表注顺序**：总说明 → 缩写 → 符号（星号以外的标记）→ 概率（*p < .05）。只定义表里真正用到的符号。

**p 值**：不写 `p = 0.000`（p 不会等于 0），写 `p < .001` 或按目标刊体例。区间写法在表、正文和摘要中保持一致。

结构检查不代替渲染后的逐页查看：列宽与断词、跨页表头、负号与上下标、黑白或色觉条件下能否区分、题注是否与表体分离，都要实际打开 Word 或 PDF 看。

## 7. 图注与表注的长度：实测参照

`assets/benchmarks/display_baseline.json` 是本机语料的实测分布（只含统计量）：

| 范围 | 条数 | 中位 | p10–p90 | 最短–最长 |
|---|---|---|---|---|
| Nature 与 Nature Communications 图注（4 篇） | 23 | 176.0 词 | 74.8–783.4 | 43–1118 |
| 其他英文开放获取全文图注（22 篇，以 arXiv、ACL、PLOS 为主） | 105 | 158.0 词 | 39.0–295.2 | 17–523 |
| 《心理学报》注释（25 篇） | 105 | 24.0 | 2.4–86.2 | — |
| 《开放教育研究》注释（26 篇） | 36 | 10.0 | 2.0–44.5 | — |

中文注释的单位是汉字加英文词。读法：**长度不是质量判据**。同一类期刊内部的长短就差了一个数量级；同为中文期刊，两刊的注释长度相差一倍以上。所以只能按同刊、同图表类型、同面板复杂度比较。

实测还显示，Nature 系列约 44% 的图注含结论句，其他英文刊约 14%。所以“图注一律不下结论”不是事实，只是复读候选。硬条件只有一条：读者只看这一图表能否读对。

`journal_check.py --baseline assets/benchmarks/display_baseline.json` 报告超长图注时，会同时给出它在实测分布中的位置。

## 8. 读者用语：内部 ID 到显示名

见 [25](25_display_terms.md)。视觉验收不只看裁切、对齐与分辨率，还要逐个读表头、行名、图例与坐标轴：读者不看代码能不能读懂。分析 CSV 的分类值不能原样进投稿表；先用 `display_terms.py template --from-tables` 把整批分析输出里的内部标签列全，核实显示名后用 `apply` 生成投稿表，未登记就不写出。版面清楚不等于用语合格。
