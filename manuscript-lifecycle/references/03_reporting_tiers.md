# 03 · 交代义务跟着主张走，然后才是篇幅与位置

先定这篇论文主张什么（论文构想，[29](29_selection_and_survey.md) §3），再判断哪些事实必须让读者知道，最后决定细节放哪里。交代义务不按“项目里做过什么”算：做过不等于欠读者。也不以避免追问为理由，隐去与主张相关的事实。

## 交代判断：按主张逐项问

一项分析或事实，有下面任一依据，就必须交代：只能决定放在哪里、写多少，不能不写。

1. **registered**：预注册、方案或公开的分析计划里写过的结局与分析；
2. **claim**：本文主张依赖它，或它会限定本文主张。包括同一主张的其他合理设定、失败的稳健性检验、同一构念的其他测量，以及被选中的发现是在多少种设定里找到的；
3. **data**：改变样本、变量意义、纳入排除或估计目标，从而影响已报告结果的数据问题与计划偏离；
4. **journal**：目标刊或报告规范的要求；
5. **ethics**：伦理、同意、利益冲突、资助、数据可得性等事实声明。

没有依据的分析不是交代义务。它可能属于另一个问题、另一篇论文，或者只是项目里的一次尝试。放不放由作者目的、审稿人反应与同类惯例决定（29），默认不进本文。

判断“和主张有没有关系”，用结果盲测试：如果它的结果正是你希望的，你会把它放进论文吗？会，它就和主张相关，结果不理想也要交代，或者收窄主张并说明原因；不会，它就不属于本文。

失败或未收敛的模型：本文主张依赖它的，说明失败及影响，不当稳健性支持；本文主张不依赖它的，是项目里的尝试，不写，与失败调试同档。

| 档 | 条件 | 处理 |
|---|---|---|
| main 正文 | 回答或实质限定本文问题；独立读正文必需 | 核心方法、承重结果和不确定性，给补充入口 |
| supp 补充 | 本文主张的完整复现、扩展结果、有依据的稳健性与限定；正文摘要足以忠实表达 | 正文交代关键影响；补充自足、可定位 |
| reserve 备答 | 没有交代依据，但审稿人可能问到；或同类论文不提就会被问、本文暂不放 | 不进论文；留依据与答案，追问时给出 |
| omit 不属于本文 | 不属于本文问题的分析；项目里的尝试与失败调试；重复输出、文件转换等没有科学含义的过程 | 留在项目档案，必要时写明“可作他文”；不等于删数据 |

同类论文帮助分配篇幅，不能免除义务。取舍不由显著性决定；关键不利结果不能藏在补充长表末端。敏感性分析若决定可信度，可以进正文图。

## 方法可读性与复现

用“目的→对象/做法→关键设定→判断标准/输出”检查完整，不强制四句模板。标准术语首次给必要说明。

报告影响结果、复现或解释的估计器、缺失处理、排除、协变量、阈值、校正、软件及版本。默认值若随版本变或影响估计仍应交代；无关参数不堆正文。公式若使核心量更清楚可进正文，长推导放补充。引用不能替代实际做法。

台账至少记 ID、计划身份、问题/结局、样本、模型、来源文件行列、值/单位/分母、位置、披露义务、理由、关联主张。相同数字但不同模型/时间点不能互换。

## 历史案例的边界

- 草率作答标记若只是无影响内部核对可归档；若据此排除样本或选择结果，应报告处理与影响。
- 扩大年龄范围若参与分析，评估伦理、人群与结果变化；不能怕同意问题而隐藏。
- 问卷改版核实是否改变已分析测量、程序或可比性；有影响必须报告。
- 独立复算不必写成自我辩护，代码可得性与复现说明仍按规范提供。

已有项目决定只对当时证据有效。新证据、期刊要求或主张变化触发重议。reserve/omit 用反事实检验：知情读者若知道此事，会改变对本文主张的判断吗？

## 去向登记：每项都写读者问题

分档的结果落进 `placement_decisions.csv`（[27](27_genre_and_placement.md) §4）：每项已做的分析、每张主文表图、正文引用的每个补充条目一行，写读者问题、去向（main / supp / omit）与依据（近邻位置或披露义务、作者须知、报告规范、用户要求）。omit 也登记，因为“做过”不是写进论文的理由；“审稿人可能会问”也不足以进补充，留在内部备答即可。必须披露的事不能 omit。投稿阶段没有这张表、读者问题空着、依据空着，genre_gate PL0–PL7 都会阻断。

## 不进稿的三种写法

“不进稿”的意思是：正文和表注里既不写“做了”，也不写“没做”。三种写法都算报告：

| 写法 | 例子 |
|---|---|
| 肯定句 | Diagnoses were verified for research purposes. |
| 否定句 | were not verified、未经研究核实、未作预注册、未筛查草率作答 |
| 侧面带出 | All solutions were proper.（读者据此知道做过一个没报告的检查）、条目层指标结果相似 |

否定句最容易被忽略。它读起来像在坦白，实际上同样把一件不进稿的事摆到了读者面前，只会引出新的追问。侧面带出更隐蔽：一句“全部正常”等于宣布“我们做过一个检查，但结果没给你看”。

**落到台账上**：定为 reserve 或 omit 的项目，关键词要把否定式写法一并列进去（not verified、未经核实），否则 `ledger_check.py` 发现不了。关键词用这项分析独有的短语，不用 model 这种泛词。

## 审稿人会不会问：预判表

这张表用来划定“不主动写”的边界，**不是用来少写**。必须披露的事先于它。

| 情况 | 不主动写 | 但如果……就必须写 |
|---|---|---|
| 数据清理与格式转换 | 是 | 清理规则改变了样本或变量取值 |
| 随机种子、迭代次数等执行记录 | 是 | 结果对种子敏感，或复现需要它（随代码公开即可） |
| 分析重跑、修正过的中间错误 | 是 | 修正改变了已报告的结果 |
| 内部复核（助研核对、独立复算） | 是 | 复核发现并改正了影响结论的错误 |
| 无影响的内部核查（如草率作答标记） | 是 | 据此排除了样本，或据此选择了报告哪个结果 |
| 未采用的探索性分析 | 是，若与本文主张无关（结果盲测试：结果理想时也不会放） | 与本文主张相关：同一主张的其他设定或测量；被选中的发现是在多种设定里找到的 |
| 失败或未收敛的模型 | 是，若本文主张不依赖它 | 本文主张依赖它，或它是检验本文问题的计划内模型 |
| 审稿人可能会问、但没有交代依据的分析 | 是（备答 reserve） | 同类论文不提就必然被问、且本文有答案：写一句并给入口 |
| 预注册状态 | 不写“未注册” | 一旦声称预定，就必须给出依据（时间戳、方案） |
| 伦理、同意、数据可得性 | 否 | 永远按事实和期刊要求写 |

反事实检验：**知情读者如果知道这件事，会改变对本文主张的判断吗？** 会，就写；不会，就归档，并在台账里登记决定依据，以备追问。写法见 `assets/exemplars/15_what_not_to_report.md`。
