# assets/exemplars · 范例库

每个文件回答同一个问题：**这一节写到什么程度才算到位。**

分布数字告诉你“偏了多少”，范例告诉你“该长什么样”。起草时先读本节范例，再动笔。只从范例里拿走两件事：

1. **这一段承担什么任务**：谁是主角，先说什么，在哪里收住；
2. **信息放多少**：数字放哪一层，限定写到哪一步。

**不要拿走措辞。** 照抄句子会让不同稿件长得一样，这本身就是机器痕迹。范例里的研究全部是合成的，数字不真实，不能当文献引用。

每个文件的结构：任务 → 坏例 → 为什么坏（逐条给出判据）→ 改写 → 这份范例不校准什么。

`<!-- test: … -->` 行供 `evals/test_benchmarks_exemplars.py` 使用：坏例必须触发列出的规则，改写不得触发。改了检查规则或范例，要重跑这个测试，否则范例会和工具脱节。
