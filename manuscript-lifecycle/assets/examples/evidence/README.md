# 可执行的数字证据示例

这是人为构造的演示，不是真实研究数据。两行故意使用同一个数值，用来说明只搜数字无法排除错结局、错组别。

在 skill 根目录执行：

```
python scripts/verify_evidence.py assets/examples/evidence/numeric_evidence.json --report evidence_report.json
```

示例返回 `verified_mechanical`，仅表示：给定稿件字节与来源字节未变、指定原文锚点唯一、CSV 行键唯一、上下文字段一致、单位与舍入匹配。它不证明相关性估计计算正确、研究设计合适或该句完整解释了研究。

改变稿件、CSV、行键、方向、单位后重跑，必须先检查失败原因；不要为了消除失败直接重算哈希或删掉检查。只有改动确属新一轮输入并经核实，才更新清单与运行回执。

`verify_evidence.py --help` 给出完整字段。`quote` 核对逐字引文与源段落；`citation` 记录访问层级、源段与人工支持性判断，但始终标为 `review_required`，因为脚本不能认证人的身份，也不能判断引用是否支持论文主张。

每个主张相关的数字分别登记。只填一个示例数字，不能覆盖全文；覆盖率需要完整结果台账、数字清单及独立抽核。中文上下文字段采用精确子串，英文采用词边界；二者均不是语义理解。单位必须来自来源定义，不应由写作模型自由猜测。
